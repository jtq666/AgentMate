# AgentMate 简历与面试表达

## 项目一句话

面向计算机保研学生设计并实现 AI Agent 专题研学平台，通过固定 Supervisor 多 Agent 流水线完成混合检索、带引用讲解、模拟面试、自动评分和薄弱点复习。

## 可写入简历的技术点

- 基于 FastAPI、Streamlit、SQLite 和 ChromaDB 构建端到端研学平台，将 Research、Teaching、Interview、Evaluation、Supervisor 拆分为职责与结构化输出明确的 Agent。
- 设计 ChromaDB + BM25 双路召回和 RRF 融合排序，为生成内容分配可追溯 `[Sx]` 引用，并在 Supervisor 阶段校验和剔除无效编号。
- 实现单并发异步任务队列、阶段级 90 秒超时与一次重试、重启中断标记、单阶段续跑，使长模型链路不阻塞前端请求。
- 使用 SQLite WAL、外键和任务隔离保存阶段产物、来源、评测证据与掌握度；取消主观打卡，以 5 题自动测评结果更新薄弱点。
- 构建覆盖 6 个专题的 24 题固定基准，对单 LLM、混合 RAG、多 Agent 和 Reflexion 完整方案进行消融，分开报告质量、引用、延迟和调用成本。
- 在 96 个真实配置样本中，混合 RAG 将必答点覆盖率由 76.0% 提升至 95.8%、引用有效率由 0% 提升至 100%；同时发现完整多 Agent 与单 Agent + RAG 覆盖率持平但成本更高，据此明确多 Agent 的适用边界。

## 面试追问准备

**为什么需要多 Agent？** 不是因为角色越多越好。Research 负责证据集合，Teaching 只能消费该证据并生成讲解，Interview 生成隐藏评分规则，Evaluation 在看到用户答案后评分，Supervisor 负责状态与引用校验；角色间存在明确的数据依赖，且可通过消融比较收益与成本。

**为什么用 RRF？** 向量相似度和 BM25 分数不可直接相加。RRF 只利用每路排名计算倒数名次分数，避免分数归一化，同时保留语义召回与精确词项召回的互补性。

**如何避免“掌握度”是伪指标？** 不使用按钮或执行轨迹生成掌握度，只接受完整面试测评作为证据。首次使用总分，后续用指数加权方式更新，并保存证据次数与最后测评时间。

**如何处理模型和外部服务不稳定？** 核心阶段超时后最多自动重试一次；论文检索是可选增强，失败只记录警告并回退本地资料；服务重启会把未完成任务标记为 interrupted，用户可从失败阶段续跑。

## 数据表述原则

本仓库的上述数字来自 `python -m agentmate.benchmarks.run_benchmark --live` 的 24 题完整运行。面试时应同时说明：完整多 Agent 并未超过单 Agent + RAG 的覆盖率，其价值体现在职责隔离、隐藏评分规则、阶段恢复和引用审计；这是实验支持的边界，而不是缺点回避。
